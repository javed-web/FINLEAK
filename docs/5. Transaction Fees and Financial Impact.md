# Stage 5 — Transaction Fees & Financial Impact

## 🎯 Objective

Until Stage 4, I had the transaction lifecycle covered:

```text
Customer
   ↓
Transaction
   ↓
Payment Attempt
   ↓
Success / Failure
   ↓
Refund / Chargeback
```

But I was still missing an important part of the financial picture:

**How much does each transaction actually cost or contribute to PayFlow?**

For this stage, I added transaction-level financial components:

- Gateway fees
- Processing fees
- Platform fees
- Discounts
- Cashback

This will later allow me to move beyond simply looking at transaction volume and start analyzing **financial contribution and leakage**.

---

## 💡 Why I Added Transaction Fees

A transaction with a large amount does not necessarily mean it is highly profitable.

For example, a transaction can generate revenue for PayFlow but also create costs through:

- Payment gateway charges
- Processing costs
- Discounts
- Cashback

So I wanted each transaction to carry its own financial information.

The basic idea is:

```text
Transaction
     │
     ├── Gateway Fee
     ├── Processing Fee
     ├── Platform Fee
     ├── Discount
     └── Cashback
```

Later, these fields will be combined with refunds and chargebacks to investigate where financial value is being lost.

---

# 🗄️ Database

The `transaction_fees` table was already part of the planned schema.

```sql
CREATE TABLE transaction_fees (
    fee_id VARCHAR(30) PRIMARY KEY,
    transaction_id VARCHAR(30) NOT NULL,
    gateway_fee DECIMAL(15,2) DEFAULT 0,
    processing_fee DECIMAL(15,2) DEFAULT 0,
    platform_fee DECIMAL(15,2) DEFAULT 0,
    discount_amount DECIMAL(15,2) DEFAULT 0,
    cashback_amount DECIMAL(15,2) DEFAULT 0,
    FOREIGN KEY (transaction_id) REFERENCES transactions(transaction_id)
);
```

Each transaction has exactly one corresponding fee record.

The relationship is:

```text
transactions
      │
      └── transaction_fees
```

# 🧠 Fee Generation Logic

I created:

```text
python/generate_transaction_fees.py
```

I used a fixed random seed so that the generated data remains reproducible.

## Gateway Fee

Gateway fees were generated as a percentage of the transaction amount.

| Gateway | Fee Rate |
|---|---:|
| Gateway_A | 1.80% |
| Gateway_B | 1.60% |
| Gateway_C | 1.50% |
| Gateway_D | 1.90% |

This gives the gateways slightly different processing costs.

---

## Processing Fee

Processing fees depend on the payment method.

| Payment Method | Processing Rate |
|---|---:|
| UPI | 0.30% |
| Credit Card | 1.20% |
| Debit Card | 0.80% |
| Net Banking | 0.60% |
| Wallet | 1.00% |

I also added a fixed **₹2 processing component** to every transaction.

---

## Platform Fee

The platform fee represents PayFlow's fee/revenue from a successful transaction.

I used:

```text
0.50% of transaction amount
```

with a maximum platform fee of:

```text
₹100
```

Failed transactions receive:

```text
platform_fee = 0
```

because the transaction was not successfully completed.

---

## Discount

Discounts are not applied to every transaction.

I used:

- 15% probability of receiving a discount
- Discount between 2% and 10% of transaction value
- Maximum discount: ₹500

Discounts are only generated for successful transactions.

---

## Cashback

Cashback is also applied only to a subset of successful transactions.

I used:

- 8% probability
- Cashback between 1% and 5% of transaction value
- Maximum cashback: ₹300

# 🧪 Test Run

Before generating fees for all 1 million transactions, I tested the generator using **10,000 transactions**.

The test generated exactly:

```text
10,000 fee records
```

The first version of the script encountered a MySQL error:

```text
mysql.connector.errors.InternalError:
Unread result found
```

This happened while closing the connection because the transaction query still had unread results.

I fixed this by using a buffered read cursor and keeping the read and write database connections separate.

After the fix, the test completed successfully.

# 🐛 Problem Encountered

The main issue in this stage was the MySQL:

```text
Unread result found
```

error.

I had already encountered the same type of problem while generating payment attempts in Stage C.

The issue came from reading a large transaction result and then trying to close the connection while the result was still considered unread.

### 🔧 Fix

I changed the database handling so that:

- Transaction reading uses a separate connection.
- Fee insertion uses another connection.
- The transaction cursor uses buffered results.

After making this change, the test and full generation completed successfully.
